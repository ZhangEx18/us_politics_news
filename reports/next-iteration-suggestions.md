## B1（P0）归因尾巴模板化 —— 旧模板的替代品

**现象**：17 段中 **14 段（82%）** 的第二句是"归因尾巴"：

| 栏目 | 第二句原文 |
|---|---|
| 美国政局 | "报道称，选举官员由此获得中期选举的邮寄投票操作指引。" |
| 美国政局 | "该机构新闻稿显示，提案同时包括对委托书征集流程的改革。" |
| 科技 | "华尔街见闻当日报道了这一表态。" |
| 科技 | "TechCrunch 当日报道了这一说法。" |
| 科技 | "英伟达博客当日发布这一消息。" |

关键词计数：`报道称`×6、`报道了`×2、`当日`×3。**旧版是"此前/此次/接下来"，新版换成了"报道称/当日报道了"。**

**根因**：DIGEST prompt 要求"媒体转述必须归因"，但未约束归因出现次数与位置，模型用归因填第二句。

**修改（`COLUMN_DIGEST_PROMPT_TEMPLATE`）**：

```diff
+**归因只出现一次**：导语已写"据X报道/据X新闻稿"时，第二、三句直接陈述事实，
+不得再写"报道称 / 报道显示 / 新闻稿显示 / 当日报道了…"
+**第二句必须是可核实的具体事实**：数字、票数、金额、日期、地点、直接引语；
+不得写成"X 当日报道了这一消息/这一说法/这一表态"，也不得用"这一说法由 X 转述"
+**禁止以"该机构"指代**：第二次提及也用简称（SEC / FTC / 欧盟委员会）
```

自检清单加：`第二句是否为具体事实而非归因？`

**验收**：归因尾巴句 ≤10%（当前 82%）。
**回归用例**：在 `prompt_cases.yaml` 增加 `digest_no_attribution_tail`（banned_regex: `当日报道了|当日发布|这一说法由|新闻稿显示`）。

## B2（P0）经济栏 0 条重点解析

**指标诊断**：`economy: 候选 17 → 硬新闻 1 → 明细 0（1 条被降级）→ 要点 1`

即评分环节把 **16/17** 条经济候选判为非硬新闻。

**第一步（诊断，必做）**：新增 `scripts/inspect_scoring.py`
- 从状态库读取当日候选 + 评分结果（需要把 `score/is_hard_news/reason/column` 落库或从跑批日志导出）
- 输出：`候选 | score | is_hard_news | column | 标题`，人工核对误判

**第二步（按结果选择）**：
- **补源**：Bloomberg/FT/WSJ 仍禁用 → 新增 `Google News site:bloomberg.com`、`site:ft.com`（tier2、cap 2）
- **评分提示**：SCORE prompt 硬新闻清单补一句"官方统计数据的发布与修订（零售销售、CPI、就业）属硬新闻"
- **兜底**：economy `min_items 7 → 4`（先保底不空栏，再补源）

**验收**：economy 明细 ≥3。

## B3（P1）跨栏目同事件重复（3 处）

**现象**：

```
[国际局势·明细#1] 欧盟委员会主席冯德莱恩邀请加拿大成为欧盟史上首个"准成员"
[美国政局·要点]   欧盟邀请加拿大成为史上首个"准成员"
[美国政局·要点]   欧盟领导人支持加拿大成为"准成员"的计划
```

**根因**：要点跨层去重只传了**本栏目**的明细标题；且该事件被归到美国政局（栏目归属错误——fallback 候选带源声明栏目，未经 AI 校正）。

**修改**：
1. `build_report`：`detailed_title_map` 改为全栏目合并列表（要点去重与全局比较）
2. 栏目归属校验：要点候选的 `column` 与全局明细冲突时，优先合并而非新增

**验收**：同一事件跨栏目出现 ≤1 次。
