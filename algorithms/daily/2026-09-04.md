# 2026-09-04 每日算法专题

> 如何在数组中为每个元素快速找到它右侧第一个更大的元素，并把朴素的双循环优化到线性时间？

## 直觉理解

如果从左到右扫描数组，很多元素在未来都会被“更大的数”一次性解决掉。与其让每个元素都去右边逐个比较，不如维护一个栈，专门保存那些“还没等到答案”的元素。这个栈保持一个单调性：栈顶到栈底对应的值通常是递增或递减的，具体取决于题目方向。当前元素一旦比栈顶大，就说明它就是栈顶元素的下一个更大元素；把栈顶弹出后继续比，直到栈里不再满足条件。这样，每个元素最多进栈一次、出栈一次，原本看起来要反复比较的工作，被集中在一次扫描里完成。单调栈的本质不是“记住所有信息”，而是只保留对未来有用的候选项，把已经失去竞争力的元素及时丢掉。

## 算法思路

这类问题的标准目标是：对数组中的每个位置 i，找到它右边第一个比它大的数；如果不存在，就返回某个默认值，比如 -1。最直接的做法是对每个 i 向右枚举，直到遇到更大的数。这样最坏情况下会退化为 O(n^2)，例如数组单调递减时，每个位置都要扫到末尾。

单调栈的做法是从左到右扫描数组，栈中保存“还没有找到下一个更大元素”的下标或数值。为了让当前元素能高效地解决旧问题，栈需要维护一种单调结构。以“下一个更大元素”为例，通常维护一个单调递减栈：栈顶元素对应的值最小，当前数 x 一来，只要 x 大于栈顶元素，就说明 x 是栈顶元素右侧第一个更大的数，直接记录答案并弹栈。弹出后继续比较，直到栈空或者栈顶不再小于 x。随后把 x 自己入栈，等待未来更大的数来解决它。

这个过程的关键在于“每个元素只会被处理常数次”。它入栈一次，未来如果被某个更大的数弹出，也只弹出一次，所以总操作是线性的。实现时通常有两种写法：一种是栈里放下标，便于在答案数组里回填位置；另一种是栈里放数值，适合只关心值本身的场景。对于算法竞赛和通用模板，放下标更稳妥，因为它可以自然处理重复值和更复杂的映射关系。

写代码时可以按这个框架组织：先创建一个答案数组，默认全设为 -1；然后遍历数组。对于当前值 nums[i]，只要栈不空且 nums[i] 大于栈顶下标对应的值，就把栈顶位置的答案更新为 nums[i]，并弹出。循环结束后，把 i 入栈。遍历完所有元素后，栈中剩下的位置说明右边没有更大的元素，它们的答案保持默认值即可。这个套路不仅适用于“下一个更大元素”，也能迁移到“下一个更小元素”“柱状图面积”“每日温度”等一系列问题，只是单调方向和比较符号会变化。

下面给出完整 Python 示例，并附一个 C++ 对照版本。Python 代码里包含简单测试用例，方便直接运行验证。

## Python 示例

```python
from typing import List


def next_greater_elements(nums: List[int]) -> List[int]:
    """返回每个元素右侧第一个更大的元素，没有则为 -1。

    使用单调递减栈，栈中存放下标。
    栈顶对应的值越小，越容易被当前元素解决。
    """
    n = len(nums)
    ans = [-1] * n
    stack: List[int] = []  # 存放下标

    for i, x in enumerate(nums):
        # 只要当前元素更大，就可以成为栈顶元素的下一个更大元素
        while stack and nums[stack[-1]] < x:
            idx = stack.pop()
            ans[idx] = x
        stack.append(i)

    return ans


def _run_tests() -> None:
    # 基础样例
    nums1 = [2, 1, 2, 4, 3]
    expected1 = [4, 2, 4, -1, -1]
    assert next_greater_elements(nums1) == expected1

    # 严格递增
    nums2 = [1, 2, 3, 4]
    expected2 = [2, 3, 4, -1]
    assert next_greater_elements(nums2) == expected2

    # 严格递减
    nums3 = [4, 3, 2, 1]
    expected3 = [-1, -1, -1, -1]
    assert next_greater_elements(nums3) == expected3

    # 存在重复元素
    nums4 = [1, 1, 2, 1]
    expected4 = [2, 2, -1, -1]
    assert next_greater_elements(nums4) == expected4

    # 只有一个元素
    nums5 = [10]
    expected5 = [-1]
    assert next_greater_elements(nums5) == expected5

    print("所有测试通过")


if __name__ == "__main__":
    _run_tests()
    # 额外演示
    demo = [2, 7, 3, 5, 4, 6, 8]
    print("输入:", demo)
    print("输出:", next_greater_elements(demo))

```

## C++ 对照

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> nextGreaterElements(const vector<int>& nums) {
    int n = (int)nums.size();
    vector<int> ans(n, -1);
    stack<int> st; // 存放下标

    for (int i = 0; i < n; ++i) {
        while (!st.empty() && nums[st.top()] < nums[i]) {
            ans[st.top()] = nums[i];
            st.pop();
        }
        st.push(i);
    }
    return ans;
}

int main() {
    vector<int> nums = {2, 1, 2, 4, 3};
    vector<int> ans = nextGreaterElements(nums);

    for (int x : ans) cout << x << ' ';
    cout << '\n';

    return 0;
}

```

## 复杂度分析

每个元素最多入栈一次、出栈一次，因此总时间复杂度是 O(n)。答案数组和栈都只需要线性额外空间，所以空间复杂度是 O(n)。相比暴力双循环的 O(n^2)，单调栈把重复比较压缩成了顺序扫描。

## 易错点

1. 把栈里存值和存下标混在一起。修复方法：优先存下标，回填答案更稳，尤其遇到重复元素时不容易出错。
2. 比较符号写反，导致维护的是错误方向的单调性。修复方法：先明确你要找的是“右侧第一个更大”还是“更小”，再决定 while 条件是 `<` 还是 `>`。
3. 忘记初始化默认答案，或者在循环结束后误以为栈里剩下的元素还能找到答案。修复方法：先把答案数组全设为 -1，栈清空后剩余元素直接保持默认值。
