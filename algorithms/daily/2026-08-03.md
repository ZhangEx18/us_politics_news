# 2026-08-03 每日算法专题

> 如何在数组中快速找到每个元素右侧第一个比它大的元素，并把暴力双循环优化到线性时间？

## 直觉理解

如果你用暴力法做“下一个更大元素”，就会让每个数去右边一个个找，像在一条长队里反复回头问“你比我大吗”。单调栈的想法是反过来：我们不让每个元素都重新搜索，而是维护一个“还没等到更大元素的人”的候选队列。这个队列从栈底到栈顶保持单调递减，这样新来的元素一旦更大，就能一次性把它左边那些比它小的人都解决掉。因为每个元素最多进栈一次、出栈一次，所以虽然看起来像在不断比较，整体却只做了线性数量的工作。它的本质不是“神奇地跳过比较”，而是把重复比较压缩成了有序的弹栈过程。只要你接受一个事实：栈顶永远是当前最有可能被下一个更大元素击中的对象，整个算法就很自然了。

## 算法思路

这类题最经典的场景是：给定一个数组，求每个位置右边第一个比它大的数。暴力做法是对每个位置向右扫描，复杂度是 O(n^2)。单调栈的目标是把“向右扫很多次”变成“每个元素只处理一次”。

做法是维护一个栈，栈里存的是元素下标，而不是元素值。栈对应的元素值从栈底到栈顶保持严格递减。遍历数组时，当前元素记为 `x`。只要栈不空，并且 `x` 比栈顶下标对应的元素更大，就说明 `x` 正好是那个栈顶元素的“下一个更大元素”。于是我们把栈顶弹出，并记录答案为 `x`。然后继续比较，直到栈顶元素已经不小于 `x`，或者栈空为止。最后把当前下标压入栈中，等待未来更大的元素来解决它。

为什么这样是对的？因为栈里保存的都是“暂时还没找到答案”的元素，而且它们按递减顺序排列。当前元素如果能解决某个较小元素，那么它也一定能解决所有比这个较小元素更靠后的、更小的元素，弹栈过程就像一串连续的连锁反应。反过来，栈中剩下的元素都比当前值大，它们不能被当前值解决，只能等待后面的元素。

如果题目问的是“右侧第一个更大元素”，就按这个顺序从左到右遍历即可。若题目要求“环形数组”，可以把数组遍历两遍，用取模模拟循环；若要求“左侧第一个更大元素”，则把遍历方向反过来，单调栈思路仍然相同。核心永远是：维护单调性，让每个元素只被压栈和弹栈一次。

下面的 Python 示例给出标准版本：输入一个数组，返回每个位置右侧第一个更大元素；如果不存在，则记为 `-1`。代码中用 `stack` 存下标，`ans` 存答案，遍历过程中不断弹出已经被当前元素“击败”的下标。为了方便理解，还附带了简单测试用例，直接运行即可查看结果。

## Python 示例

```python
from typing import List


def next_greater_elements(nums: List[int]) -> List[int]:
    """返回每个元素右侧第一个更大元素；不存在则返回 -1。"""
    n = len(nums)
    ans = [-1] * n
    stack = []  # 栈中存下标，保证对应的 nums 值从栈底到栈顶单调递减

    for i, x in enumerate(nums):
        # 当前元素 x 可以作为栈顶元素的“下一个更大元素”
        while stack and nums[stack[-1]] < x:
            idx = stack.pop()
            ans[idx] = x
        # 当前下标入栈，等待后面的更大元素
        stack.append(i)

    return ans


if __name__ == "__main__":
    tests = [
        [2, 1, 2, 4, 3],
        [1, 3, 4, 2],
        [5, 4, 3, 2, 1],
        [1, 2, 3, 4],
        [2, 2, 2],
    ]

    for arr in tests:
        print("nums =", arr)
        print("ans  =", next_greater_elements(arr))
        print("-")

```

## C++ 对照

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> nextGreaterElements(const vector<int>& nums) {
    int n = (int)nums.size();
    vector<int> ans(n, -1);
    vector<int> st; // 存下标，栈中对应值保持单调递减

    for (int i = 0; i < n; ++i) {
        while (!st.empty() && nums[st.back()] < nums[i]) {
            ans[st.back()] = nums[i];
            st.pop_back();
        }
        st.push_back(i);
    }

    return ans;
}

int main() {
    vector<vector<int>> tests = {
        {2, 1, 2, 4, 3},
        {1, 3, 4, 2},
        {5, 4, 3, 2, 1},
        {1, 2, 3, 4},
        {2, 2, 2}
    };

    for (const auto& arr : tests) {
        auto ans = nextGreaterElements(arr);
        cout << "nums = ";
        for (int x : arr) cout << x << ' ';
        cout << "\nans  = ";
        for (int x : ans) cout << x << ' ';
        cout << "\n-\n";
    }

    return 0;
}
```

## 复杂度分析

每个元素最多入栈一次、出栈一次，因此总时间复杂度是 O(n)。栈中最多保存 n 个下标，额外空间复杂度是 O(n)。相比暴力双循环的 O(n^2)，单调栈能把重复比较压缩成一次线性扫描。

## 易错点

1. 把栈里存值而不是存下标，导致无法准确写回对应位置的答案。修复方法：栈里存下标，比较时再访问 nums[下标]。
2. 把弹栈条件写成 `<=` 或 `<` 但没有想清楚题意，导致相等元素被错误弹出或保留。修复方法：如果题目要求“严格更大”，通常用 `<`；如果要求“更大或等于”，再改成 `<=`。
3. 只想到从左到右遍历，却忘了答案是“右侧第一个更大元素”，于是把已经出现过的左边元素误当成答案。修复方法：确认方向，右侧问题就从左到右扫描并在未来元素到来时结算。
