# 2026-07-11 每日算法专题

> 如何在数组中快速找到每个元素右侧第一个比它大的元素，并把暴力双循环优化到线性时间？

## 直觉理解

如果你用暴力法找“下一个更大元素”，每个数都向右扫一遍，最坏要做很多重复比较。单调栈的想法很像“排队的人”：我们只保留那些还没找到更大元素、并且按某种顺序站好的元素。当前新来的元素一旦比队尾更大，就说明队尾的人等到了答案，可以立刻出栈；而且它还可能继续帮助前面更多人找到答案，所以会连续弹出。这样一来，每个元素最多进栈一次、出栈一次，所有比较都变成了有组织的处理，而不是反复回头检查。单调栈的本质不是“记住所有信息”，而是用一个有序的候选集合，把已经没有价值的元素尽早丢掉，只保留对未来有用的部分。对于“下一个更大元素”这类问题，栈里维护的是从栈底到栈顶递减的元素，这样当前元素才能迅速扫清它左边那些比自己小的“等待者”。

## 算法思路

先把问题想成：对于数组中的每个位置 i，我们都要找它右边第一个比 nums[i] 大的数。暴力做法是对每个 i 往右扫，效率很低。单调栈的优化方式是反过来思考：从左到右遍历数组，把“还没找到答案”的元素下标放进栈里，并保证栈顶对应的值总是最小的候选之一，但整体保持递减。这样当新元素 nums[i] 到来时，只要它比栈顶元素大，就说明栈顶元素的下一个更大元素找到了，答案就是 nums[i]，然后把栈顶弹出。继续比较，直到栈顶不再小于 nums[i] 为止。这个过程中，当前元素不仅解决了自己左边比它小的一串元素，还把这些元素从候选集中删除了，因为它们已经有答案，不必再参与后续比较。

为了方便实现，我们通常先创建一个答案数组 ans，默认值设为 -1，表示右侧没有更大元素。遍历过程中，栈里存的是下标而不是值，这样既能访问位置，也能写回答案。对于每个 i，执行“while 栈非空且 nums[i] > nums[栈顶]：弹出栈顶并令 ans[栈顶] = nums[i]”。循环结束后，再把 i 入栈。遍历完成后，仍留在栈中的元素说明它们右侧没有更大元素，答案保持 -1 即可。

这个框架的关键是“单调性”：栈内元素对应的值始终保持递减。正因为这个顺序，当一个新数出现时，所有比它小的旧元素都会被连续解决；而比它大的旧元素会安全留在栈中，等待将来更大的数来处理。这个性质让每个元素只会被压栈一次、弹栈一次，因此整体是线性的。若题目要求的是“左侧第一个更大元素”或“循环数组中的下一个更大元素”，只需要稍微调整遍历方向或重复扫描方式，核心思想完全一样。

## Python 示例

```python
from typing import List


def next_greater_elements(nums: List[int]) -> List[int]:
    """返回每个元素右侧第一个更大元素；若不存在则为 -1。"""
    n = len(nums)
    ans = [-1] * n
    stack = []  # 存下标，栈内对应的 nums 值保持递减

    for i, x in enumerate(nums):
        # 当前元素 x 解决栈顶及其后续所有比它小的元素
        while stack and x > nums[stack[-1]]:
            j = stack.pop()
            ans[j] = x
        stack.append(i)

    return ans


def _run_tests() -> None:
    # 基础测试
    assert next_greater_elements([2, 1, 2, 4, 3]) == [4, 2, 4, -1, -1]
    assert next_greater_elements([1, 2, 3, 4]) == [2, 3, 4, -1]
    assert next_greater_elements([4, 3, 2, 1]) == [-1, -1, -1, -1]
    assert next_greater_elements([1, 1, 1]) == [-1, -1, -1]
    assert next_greater_elements([]) == []

    # 题意理解测试：每个位置找右侧第一个更大元素
    assert next_greater_elements([1, 3, 2, 4]) == [3, 4, 4, -1]
    assert next_greater_elements([6, 5, 4, 3, 2, 1, 7]) == [7, 7, 7, 7, 7, 7, -1]

    print("所有测试通过")


if __name__ == "__main__":
    _run_tests()
    # 额外演示
    nums = [2, 1, 2, 4, 3]
    print("输入:", nums)
    print("输出:", next_greater_elements(nums))

```

## C++ 对照

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> nextGreaterElements(const vector<int>& nums) {
    int n = (int)nums.size();
    vector<int> ans(n, -1);
    stack<int> st; // 存下标，栈内对应值保持递减

    for (int i = 0; i < n; ++i) {
        while (!st.empty() && nums[i] > nums[st.top()]) {
            ans[st.top()] = nums[i];
            st.pop();
        }
        st.push(i);
    }
    return ans;
}

int main() {
    vector<vector<int>> tests = {
        {2, 1, 2, 4, 3},
        {1, 2, 3, 4},
        {4, 3, 2, 1},
        {1, 1, 1},
        {},
        {1, 3, 2, 4},
        {6, 5, 4, 3, 2, 1, 7}
    };

    for (const auto& nums : tests) {
        auto ans = nextGreaterElements(nums);
        cout << "nums: ";
        for (int x : nums) cout << x << ' ';
        cout << "\nans : ";
        for (int x : ans) cout << x << ' ';
        cout << "\n\n";
    }
    return 0;
}

```

## 复杂度分析

每个元素最多入栈一次、出栈一次，所以总时间复杂度是 O(n)。栈中最多同时保存 n 个下标，答案数组也需要 O(n) 空间，因此空间复杂度是 O(n)。相比暴力枚举的 O(n^2)，在数组长度较大时提升非常明显。

## 易错点

1. 把栈里存成值而不是下标，导致找到答案后不知道该更新答案数组的哪个位置，修复方法是栈中保存位置，下标和数值分开处理。
2. 把比较条件写反成 `x < nums[stack[-1]]` 或者把 `>=` 误写成 `>`，会改变“下一个更大元素”的语义，修复方法是先明确题目要“严格更大”还是“更大或相等”，再固定比较符号。
3. 忘记在遍历结束后让未出栈的元素保持 `-1`，或者试图再额外扫描一次，修复方法是初始化答案数组为 `-1`，未被弹出的元素自然就是没有更大元素。

## 延伸练习
