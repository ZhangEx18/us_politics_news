单调栈：一眼看穿下一个更大元素

进阶
栈单调栈数组
如何在数组中快速找到每个元素右侧第一个比它大的元素，并把暴力的双重循环优化到线性时间？

直觉理解

把数组从左到右扫一遍时，我们关心的不是“所有后面的元素”，而是“谁最先比我大”。如果一个元素还没找到答案，它就暂时留在栈里等待；一旦来了一个更大的数，它就像“通知”了栈顶那些更小的元素：你们的下一个更大元素找到了。更妙的是，栈里只保留一条从栈底到栈顶递减的队列，这样新元素一来，只需要不断弹出比它小的元素，就能一次性解决一批人的问题。每个元素最多进栈一次、出栈一次，所以虽然看起来像在不断比较，实际总工作量是线性的。单调栈的本质，就是把“重复比较未来很多次”的过程，改造成“只在关键时刻结算”的过程。

算法思路

我们以“下一个更大元素（Next Greater Element）”为例，目标是：对数组中的每个位置 i，找到它右边第一个比 nums[i] 大的元素；如果不存在，就记为 -1。暴力做法是对每个 i 向右扫描，最坏要 O(n^2)。单调栈的优化思路是：维护一个栈，里面存放“还没找到答案”的元素下标，并保证这些下标对应的值从栈底到栈顶单调递减。 从左到右遍历数组 nums。当前元素是 nums[i]。只要栈顶元素对应的值小于 nums[i]，就说明当前元素正好是它右侧遇到的第一个更大元素，于是可以把栈顶弹出，并把答案记录为 nums[i]。注意，这一步是“批处理”：一个更大的数可能一次性解决栈里多个更小元素。直到栈空或者栈顶元素不小于 nums[i]，再把当前下标 i 入栈，表示它也在等待未来更大的元素。 为什么栈中要存下标而不是数值？因为我们最终要给每个位置写答案，存下标更方便定位；如果题目允许数组中有重复值，存下标也能避免混淆。遍历结束后，栈里剩下的元素右侧已经没有更大元素了，它们的答案保持为 -1 即可。 这个框架不仅适用于“下一个更大元素”，也能改造成“下一个更小元素”“前一个更大元素”等问题。核心永远是：用一个单调结构保存尚未结算的元素，让新来的元素负责解决一批旧问题，从而把重复比较压缩到线性复杂度。

Python 示例

from typing import List


def next_greater_elements(nums: List[int]) -> List[int]:
    """
    返回数组中每个元素右侧第一个更大元素；若不存在，返回 -1。
    使用单调递减栈，栈中存下标。
    """
    n = len(nums)
    ans = [-1] * n
    stack = []  # 存放下标，保证 nums[stack] 从栈底到栈顶单调递减

    for i, x in enumerate(nums):
        # 当前元素比栈顶元素大，说明找到了栈顶元素的下一个更大元素
        while stack and nums[stack[-1]] < x:
            idx = stack.pop()
            ans[idx] = x
        # 当前元素还没有找到答案，先入栈等待未来元素
        stack.append(i)

    return ans


if __name__ == "__main__":
    # 测试用例 1：普通情况
    nums1 = [2, 1, 2, 4, 3]
    print("输入:", nums1)
    print("输出:", next_greater_elements(nums1))  # 期望 [4, 2, 4, -1, -1]

    # 测试用例 2：严格递减
    nums2 = [5, 4, 3, 2, 1]
    print("输入:", nums2)
    print("输出:", next_greater_elements(nums2))  # 期望 [-1, -1, -1, -1, -1]

    # 测试用例 3：严格递增
    nums3 = [1, 2, 3, 4]
    print("输入:", nums3)
    print("输出:", next_greater_elements(nums3))  # 期望 [2, 3, 4, -1]

    # 测试用例 4：含重复元素
    nums4 = [1, 1, 2, 1]
    print("输入:", nums4)
    print("输出:", next_greater_elements(nums4))  # 期望 [2, 2, -1, -1]

C++ 对照

#include <bits/stdc++.h>
using namespace std;

vector<int> nextGreaterElements(const vector<int>& nums) {
    int n = (int)nums.size();
    vector<int> ans(n, -1);
    stack<int> st; // 存下标，维护对应值单调递减

    for (int i = 0; i < n; ++i) {
        while (!st.empty() && nums[st.top()] < nums[i]) {
            int idx = st.top();
            st.pop();
            ans[idx] = nums[i];
        }
        st.push(i);
    }
    return ans;
}

int main() {
    vector<vector<int>> tests = {
        {2, 1, 2, 4, 3},
        {5, 4, 3, 2, 1},
        {1, 2, 3, 4},
        {1, 1, 2, 1}
    };

    for (auto &nums : tests) {
        auto ans = nextGreaterElements(nums);
        cout << "输入: ";
        for (int x : nums) cout << x << ' ';
        cout << "\n输出: ";
        for (int x : ans) cout << x << ' ';
        cout << "\n\n";
    }
    return 0;
}

复杂度分析

每个元素最多入栈一次、出栈一次，因此总时间复杂度是 O(n)。栈中最坏会存下全部元素，空间复杂度是 O(n)。相比暴力枚举的 O(n^2)，当数组长度很大时优势非常明显。

易错点

  1. 把栈里存“值”而不是“下标”，当数组有重复元素时会搞不清答案对应哪个位置；修复方法是存下标，写答案时用下标定位。
  2. 把比较条件写成 `<=`，会把相等元素也弹掉，导致“严格更大”被误判成“更大或相等”；如果题目要求严格更大，条件必须是 `<`。
  3. 忘记初始化答案为 -1，或遍历结束后试图再补栈内元素的答案；其实栈内剩余元素默认就表示右侧没有更大元素，直接保留 -1 即可。

延伸练习

  1. 基础练习：把本题改成“下一个更小元素”，要求返回每个元素右侧第一个更小的值。
  2. 拓展练习：实现“循环数组的下一个更大元素”，即数组末尾后面接着从头继续找，直到回到原位置为止。
