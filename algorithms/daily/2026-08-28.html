单调栈：快速找到下一个更大元素

进阶
栈单调栈数组
如何在线性时间内，为数组中的每个元素找到右侧第一个更大的元素？

直觉理解

暴力做法是对每个位置都向右扫描，直到找到一个更大的数为止，这样最坏会退化成双重循环。单调栈的核心想法是：把“还没找到答案”的元素按某种顺序暂存在栈里，并且让它们保持单调。对“下一个更大元素”这类问题，我们通常维护一个从栈底到栈顶单调递减的栈。这样一来，新来的元素只要比栈顶大，就可以连续弹出栈顶那些更小的元素，因为它们的答案已经被当前元素确定了。每个元素最多进栈一次、出栈一次，所以总复杂度是线性的。它本质上是在利用“当前元素会一次性解决一批更弱候选”的规律，把重复比较压缩掉。

算法思路

先明确问题：对于数组中的每个位置 i，要找到它右边第一个严格大于 nums[i] 的元素；如果不存在，就记为 -1。直接暴力枚举右侧所有位置，虽然容易写，但重复比较太多。单调栈的做法是从左到右扫描数组，栈里保存的是“还没找到下一个更大元素”的下标，且这些下标对应的值从栈底到栈顶保持递减。 当我们处理当前元素 nums[i] 时，只要它比栈顶下标对应的值更大，就说明栈顶元素的“下一个更大元素”已经找到了，而且就是 nums[i]。于是不断弹栈，直到栈空或栈顶元素不小于当前值为止。弹出的每个位置都可以立刻填写答案。等这些都处理完，再把当前下标压入栈中，等待未来更大的元素来解决它。 这个过程之所以高效，是因为每个元素只会经历两件事：被压入栈一次，以及在未来某一时刻被弹出一次。不会出现反复回头比较的情况。实现时通常用下标而不是数值入栈，这样既能回填答案，也能正确处理重复元素。若题目要求“下一个更大元素”，比较条件应是严格大于；如果题目改成“下一个更大或相等元素”，弹栈条件也要相应改掉。 实际写题时，可以统一把答案初始化为 -1，然后扫描数组。对于每个位置，先处理所有比当前值小的栈顶元素，再把自己放进栈里。最后栈中剩下的位置都没有找到更大元素，答案保持 -1 即可。这个模板也可以推广到“下一个更小元素”“接雨水”“柱状图最大矩形”等很多经典题目，本质都是用单调性减少无效比较。

Python 示例

from typing import List


def next_greater_elements(nums: List[int]) -> List[int]:
    """返回每个元素右侧第一个更大元素；若不存在则为 -1。"""
    n = len(nums)
    ans = [-1] * n
    stack = []  # 存下标，且对应 nums 值保持单调递减

    for i, x in enumerate(nums):
        # 当前元素 x 解决掉所有比它小的元素
        while stack and nums[stack[-1]] < x:
            j = stack.pop()
            ans[j] = x
        stack.append(i)

    return ans


def _test():
    cases = [
        ([2, 1, 2, 4, 3], [4, 2, 4, -1, -1]),
        ([1, 2, 3, 4], [2, 3, 4, -1]),
        ([4, 3, 2, 1], [-1, -1, -1, -1]),
        ([2, 2, 2], [-1, -1, -1]),
        ([1, 3, 2, 5, 4], [3, 5, 5, -1, -1]),
    ]
    for nums, expected in cases:
        got = next_greater_elements(nums)
        assert got == expected, f"nums={nums}, expected={expected}, got={got}"
    print("所有测试通过")


if __name__ == "__main__":
    _test()

C++ 对照

#include <bits/stdc++.h>
using namespace std;

vector<int> nextGreaterElements(const vector<int>& nums) {
    int n = (int)nums.size();
    vector<int> ans(n, -1);
    stack<int> st; // 存下标，nums[st] 单调递减

    for (int i = 0; i < n; ++i) {
        while (!st.empty() && nums[st.top()] < nums[i]) {
            int j = st.top();
            st.pop();
            ans[j] = nums[i];
        }
        st.push(i);
    }
    return ans;
}

int main() {
    vector<vector<int>> tests = {
        {2, 1, 2, 4, 3},
        {1, 2, 3, 4},
        {4, 3, 2, 1},
        {2, 2, 2},
        {1, 3, 2, 5, 4}
    };
    vector<vector<int>> expected = {
        {4, 2, 4, -1, -1},
        {2, 3, 4, -1},
        {-1, -1, -1, -1},
        {-1, -1, -1},
        {3, 5, 5, -1, -1}
    };

    for (size_t t = 0; t < tests.size(); ++t) {
        auto got = nextGreaterElements(tests[t]);
        assert(got == expected[t]);
    }
    cout << "所有测试通过" << endl;
    return 0;
}

复杂度分析

每个元素最多入栈一次、出栈一次，因此总时间复杂度是 O(n)。栈中最多保存 n 个下标，额外空间复杂度是 O(n)。相比暴力做法的 O(n^2)，单调栈把重复比较压缩到了线性级别。

易错点

  1. 把值入栈而不是下标入栈，导致无法回填答案或在有重复元素时判断混乱；修复方法是始终存下标，再通过下标访问原数组。
  2. 把比较条件写成 <= 或 >=，把“严格更大”和“更大或相等”混为一谈；修复方法是先确认题意，再只用严格小于 nums[i] 的元素被弹出。
  3. 扫描方向和栈的单调方向不匹配，结果虽然能写出代码但答案错位；修复方法是先固定一种模板，左到右扫描时维护递减栈，当前元素负责解决栈顶更小元素。

延伸练习
