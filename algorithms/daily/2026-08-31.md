# 2026-08-31 每日算法专题

> 如何在线性时间内，为数组中的每个元素找到它右边第一个比它大的元素？

## 直觉理解

如果把问题直接拆成“对每个位置都向右扫一遍”，那么最坏情况下会做很多重复比较，比如数组单调递减时，每个元素都要把右边的大半段重新看一遍。单调栈的核心想法，是把这些已经没用的比较结果提前清理掉。我们从左到右处理数组，栈里保存的不是所有元素，而是一批还“有资格被别人找到”的元素，并且让它们保持一种单调关系。当前元素一来，就把栈顶那些比它小的元素全部弹出，因为当前元素已经证明它们的“下一个更大元素”就是自己；这些更小元素以后再也不可能成为更左边元素的答案了。这样，每个元素最多进栈一次、出栈一次，看似反复维护，实际上总工作量是线性的。它本质上是在利用顺序和单调性，把“未来会不会被更大的数覆盖”这个判断提前完成。

## 算法思路

这类题的目标通常是：对数组中的每个位置 i，找到右侧第一个满足 nums[j] > nums[i] 的位置 j；如果不存在，就记为 -1。直接暴力做法是对每个 i 向右扫描，时间复杂度是 O(n^2)。单调栈的做法是把“还没找到答案的元素”集中放进一个栈里，并让栈中的元素保持从栈底到栈顶单调递减。处理到当前元素 x 时，说明 x 可以作为一批更小元素的答案：只要栈顶元素小于 x，就不断弹出栈顶，并把它们的答案更新成 x。因为当前的 x 是从左到右顺序到来的，所以它一定是这些被弹出元素右侧遇到的第一个更大元素。弹出结束后，再把 x 放进栈中，等待未来更大的数来处理它。

如果题目要求输出“每个位置右边第一个更大元素的值”，可以直接用栈中存下标，方便回填答案数组；如果只想判断“是否存在更大元素”，也可以存值，但存下标更通用。实现时通常准备一个与原数组等长的答案数组，初始填 -1。遍历数组时，栈里存的是还没有找到答案的下标，且对应值保持递减。每读到一个新值，就先结算所有比它小的下标，再把当前下标压栈。遍历结束后，栈里剩下的元素右侧已经没有更大值，因此答案保持 -1。

这套框架的关键不是“记住一个固定模板”，而是抓住两点：第一，栈里保存的是“等待被解决的问题”；第二，一旦某个更大的元素出现，它会一次性解决一批更小元素。只要题目和“右边第一个更大/更小”有关，通常都可以优先考虑单调栈。

## Python 示例

```python
from typing import List

def next_greater_elements(nums: List[int]) -> List[int]:
    """
    返回每个元素右边第一个更大的元素；如果不存在，则为 -1。
    使用单调递减栈，栈中存下标。
    """
    n = len(nums)
    ans = [-1] * n
    stack = []  # 存放下标，对应的值保持单调递减

    for i, x in enumerate(nums):
        # 当前元素 x 比栈顶元素大，说明它就是栈顶元素的下一个更大元素
        while stack and nums[stack[-1]] < x:
            idx = stack.pop()
            ans[idx] = x
        # 当前元素先入栈，等待未来更大的元素来处理它
        stack.append(i)

    return ans


def run_tests():
    # 基础测试
    nums1 = [2, 1, 2, 4, 3]
    expected1 = [4, 2, 4, -1, -1]
    assert next_greater_elements(nums1) == expected1

    # 严格递增：每个元素的下一个更大元素就是右边紧邻的元素
    nums2 = [1, 2, 3, 4]
    expected2 = [2, 3, 4, -1]
    assert next_greater_elements(nums2) == expected2

    # 严格递减：所有元素右边都没有更大元素
    nums3 = [5, 4, 3, 2, 1]
    expected3 = [-1, -1, -1, -1, -1]
    assert next_greater_elements(nums3) == expected3

    # 含重复元素：相等不算更大
    nums4 = [2, 2, 3, 2]
    expected4 = [3, 3, -1, -1]
    assert next_greater_elements(nums4) == expected4

    # 单元素
    nums5 = [10]
    expected5 = [-1]
    assert next_greater_elements(nums5) == expected5

    print("所有测试通过")


if __name__ == "__main__":
    run_tests()
```

## C++ 对照

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> nextGreaterElements(const vector<int>& nums) {
    int n = (int)nums.size();
    vector<int> ans(n, -1);
    stack<int> st; // 存下标，保持对应值单调递减

    for (int i = 0; i < n; ++i) {
        while (!st.empty() && nums[st.top()] < nums[i]) {
            ans[st.top()] = nums[i];
            st.pop();
        }
        st.push(i);
    }

    return ans;
}

int main() {
    vector<vector<int>> tests = {
        {2, 1, 2, 4, 3},
        {1, 2, 3, 4},
        {5, 4, 3, 2, 1},
        {2, 2, 3, 2},
        {10}
    };

    for (const auto& nums : tests) {
        auto ans = nextGreaterElements(nums);
        for (int x : ans) cout << x << ' ';
        cout << '\n';
    }

    return 0;
}
```

## 复杂度分析

每个元素最多入栈一次、出栈一次，因此总时间复杂度为 O(n)。栈中最多保存 n 个下标，答案数组也需要 O(n) 空间，所以空间复杂度为 O(n)。相比暴力双循环的 O(n^2)，单调栈把重复比较压缩掉了。

## 易错点

1. 把“右边第一个更大元素”写成“右边任意一个更大元素”。修复方法是始终按从左到右扫描，并在第一次遇到更大值时立刻弹栈回填，不能继续找更后面的值。
2. 用 `<=` 代替 `<`，导致相等元素被错误当成更大元素。修复方法是明确题意：只有严格大于才算答案；相等时不能弹栈。
3. 栈里存值而不是下标，回填答案时容易丢失位置。修复方法是优先存下标，这样既能取值比较，也能把结果准确写回对应位置。
