单调栈：一次遍历找到下一个更大元素

进阶
栈单调栈数组
如何在线性时间内为数组中每个元素找到右侧第一个比它大的元素？

直觉理解

如果你对每个元素都向右暴力找“第一个更大值”，最坏情况下会把很多位置反复扫一遍，复杂度很快就变成 O(n^2)。单调栈的核心想法，是把“还没找到答案的元素”按某种顺序集中保存起来，让新来的元素一次性帮助多个旧元素结算答案。对于“下一个更大元素”问题，我们维护一个从栈底到栈顶单调递减的栈：栈里放的是元素的下标，栈顶总是当前最“弱”的候选。每当扫描到一个新元素时，只要它比栈顶元素大，就说明它就是栈顶那个元素右侧第一个更大的数，可以立刻把答案填上并弹栈。这个过程像是不断清账：小的元素一旦被更大的元素挡住，就不再有机会成为别人的“下一个更大元素”。因为每个元素最多入栈一次、出栈一次，所以虽然看起来像在循环里反复弹栈，整体仍然是线性的。

算法思路

先明确题意：对数组中的每个位置 i，找到它右边第一个比 nums[i] 大的元素；如果不存在，就记为 -1。朴素做法是从 i+1 开始一路往右找，直到遇到更大的数为止，但这会重复扫描大量区间。 单调栈的做法是从左到右遍历数组，同时维护一个“还没找到答案”的下标栈，且栈中对应的值保持严格递减。这里存下标而不是直接存值，原因是我们既要比较大小，也要把答案写回到具体位置。遍历到当前元素 nums[i] 时，先检查栈顶对应的元素是否比它小：如果是，说明当前元素就是那个位置的下一个更大元素，直接把答案数组中对应位置更新为 nums[i]，然后弹出栈顶。这个弹栈过程可能连续发生多次，因为当前元素可能一次性解决多个更小的元素。等到栈顶不再小于当前值时，再把当前下标压入栈中，等待未来更大的元素来解决它。 这样做的本质是把“未来会被谁解决”提前组织好。栈中的元素按大小递减排列，越靠近栈顶的元素越容易被新元素结算；一旦某个位置被结算，它就不会再参与后续比较，因此不会产生重复工作。遍历结束后，栈中剩下的元素都没有找到更大的右侧元素，答案保持为 -1 即可。这个框架非常稳定，很多题目都可以套用：只要你关心“左边/右边第一个更大或更小的元素”，通常都能考虑单调栈。

Python 示例

from typing import List


def next_greater_elements(nums: List[int]) -> List[int]:
    """
    返回每个位置右侧第一个更大的元素。
    如果不存在，则返回 -1。
    使用单调递减栈，栈中保存下标。
    """
    n = len(nums)
    ans = [-1] * n
    stack = []  # 单调递减栈：栈内下标对应的值从栈底到栈顶递减

    for i, x in enumerate(nums):
        # 当前元素比栈顶元素大，说明它就是栈顶位置的下一个更大元素
        while stack and nums[stack[-1]] < x:
            idx = stack.pop()
            ans[idx] = x
        # 当前下标入栈，等待未来更大的元素来更新答案
        stack.append(i)

    return ans


def main() -> None:
    # 测试用例1：基础示例
    nums1 = [2, 1, 2, 4, 3]
    print(next_greater_elements(nums1))  # 期望输出 [4, 2, 4, -1, -1]

    # 测试用例2：严格递减，所有元素都找不到更大值
    nums2 = [5, 4, 3, 2, 1]
    print(next_greater_elements(nums2))  # 期望输出 [-1, -1, -1, -1, -1]

    # 测试用例3：严格递增，每个元素的下一个更大值都是右侧紧邻元素
    nums3 = [1, 2, 3, 4]
    print(next_greater_elements(nums3))  # 期望输出 [2, 3, 4, -1]

    # 测试用例4：包含重复元素
    nums4 = [2, 2, 1, 3]
    print(next_greater_elements(nums4))  # 期望输出 [3, 3, 3, -1]


if __name__ == "__main__":
    main()

C++ 对照

#include <bits/stdc++.h>
using namespace std;

vector<int> nextGreaterElements(const vector<int>& nums) {
    int n = (int)nums.size();
    vector<int> ans(n, -1);
    stack<int> st; // 单调递减栈，保存下标

    for (int i = 0; i < n; ++i) {
        while (!st.empty() && nums[st.top()] < nums[i]) {
            int idx = st.top();
            st.pop();
            ans[idx] = nums[i];
        }
        st.push(i);
    }
    return ans;
}

int main() {
    vector<int> nums1 = {2, 1, 2, 4, 3};
    vector<int> res1 = nextGreaterElements(nums1);
    for (int x : res1) cout << x << ' ';
    cout << '\n';

    vector<int> nums2 = {5, 4, 3, 2, 1};
    vector<int> res2 = nextGreaterElements(nums2);
    for (int x : res2) cout << x << ' ';
    cout << '\n';

    vector<int> nums3 = {1, 2, 3, 4};
    vector<int> res3 = nextGreaterElements(nums3);
    for (int x : res3) cout << x << ' ';
    cout << '\n';

    vector<int> nums4 = {2, 2, 1, 3};
    vector<int> res4 = nextGreaterElements(nums4);
    for (int x : res4) cout << x << ' ';
    cout << '\n';

    return 0;
}

复杂度分析

每个元素最多入栈一次、出栈一次，因此总时间复杂度是 O(n)。答案数组和栈都只会额外使用 O(n) 空间。虽然代码里有 while 循环，但它不是嵌套放大复杂度，因为每次弹出的元素都不会再回来参与比较。

易错点

  1. 把栈里存值而不是存下标，导致重复元素时无法正确回填答案；修复方法是统一存下标，比较时再取 nums[下标]。
  2. 把弹栈条件写成 <=，会把相等元素错误地当成更大元素；修复方法是严格使用 <，因为题目要求的是“更大”而不是“更大或相等”。
  3. 只在栈顶弹一次就入栈当前元素，漏掉连续多个更小元素的结算；修复方法是用 while 一直弹到栈顶不再小于当前值。
