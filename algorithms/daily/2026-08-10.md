# 2026-08-10 每日算法专题

> 如何在数组中快速找到两个数，使它们的和等于目标值？

## 直觉理解

这道题的本质，是把“找搭档”这件事从慢慢比对，变成边看边记。最直接的想法是：拿每个数去和后面的所有数配对，看看有没有加起来等于目标值的组合。这样虽然简单，但每次都要重新扫描，效率很低。哈希表的作用，就是提前把“我见过什么数”记下来，并且能在很短时间内查到某个数是否出现过。当前数字是 x，想凑出 target，就只需要看看 target - x 之前是否已经出现过。如果出现过，这两个数立刻组成答案。这个过程像是在排队时先登记名字，后面需要找人时直接查名单，而不是挨个问一遍。它体现了算法里最经典的思路之一：用更多的空间，换更少的时间。

## 算法思路

先从暴力法理解问题：对数组中的每个元素 nums[i]，再去检查它后面的每个元素 nums[j]，如果 nums[i] + nums[j] == target，就返回这两个下标。这个方法的优点是思路直观，缺点是时间复杂度是 O(n^2)，当数组变长时会明显变慢。

优化的关键在于“反过来想”。如果当前看到一个数 x，那么为了凑出 target，我们真正需要找的是另一个数 y = target - x。与其在数组里反复搜索 y，不如在遍历过程中把已经出现过的数存到哈希表里。这样当我们处理到 x 时，只要判断 y 是否在哈希表中即可，查找操作平均是 O(1)。

具体做法是从左到右遍历数组。每到一个元素 x，先计算补数 y = target - x。若 y 已经在哈希表中，说明之前某个位置的数和当前 x 正好配对，直接返回这两个下标。若 y 不在，再把 x 和它的下标存入哈希表，供后面的元素使用。这里有一个细节：一定要先查找，再插入，避免同一个元素被重复使用。

这个框架很通用：遍历数组 + 哈希表记录历史信息 + 用补数思维快速定位答案。只要题目出现“找两数满足某个关系”，就可以优先考虑这种写法。

## Python 示例

```python
from typing import List


def two_sum(nums: List[int], target: int) -> List[int]:
    """返回两个下标，使得 nums[i] + nums[j] == target。"""
    # 哈希表：键是数值，值是这个数第一次出现时的下标
    seen = {}

    # 从左到右扫描数组
    for i, x in enumerate(nums):
        need = target - x  # 当前数需要的搭档

        # 如果搭档已经出现过，直接返回答案
        if need in seen:
            return [seen[need], i]

        # 先查再存，避免同一个元素被重复使用
        seen[x] = i

    # 题目通常保证有解；这里写上是为了函数更完整
    return []


if __name__ == "__main__":
    # 基础测试
    print(two_sum([2, 7, 11, 15], 9))      # [0, 1]
    print(two_sum([3, 2, 4], 6))           # [1, 2]
    print(two_sum([3, 3], 6))              # [0, 1]

    # 用断言做简单自测
    assert two_sum([2, 7, 11, 15], 9) == [0, 1]
    assert two_sum([3, 2, 4], 6) == [1, 2]
    assert two_sum([3, 3], 6) == [0, 1]

    print("所有测试通过")
```

## C++ 对照

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> twoSum(const vector<int>& nums, int target) {
    unordered_map<int, int> seen; // 数值 -> 下标

    for (int i = 0; i < (int)nums.size(); ++i) {
        int x = nums[i];
        int need = target - x;

        // 先查找补数是否已经出现过
        auto it = seen.find(need);
        if (it != seen.end()) {
            return {it->second, i};
        }

        // 再把当前数放入哈希表
        seen[x] = i;
    }

    return {};
}

int main() {
    vector<int> a = {2, 7, 11, 15};
    vector<int> b = {3, 2, 4};
    vector<int> c = {3, 3};

    auto r1 = twoSum(a, 9);
    auto r2 = twoSum(b, 6);
    auto r3 = twoSum(c, 6);

    cout << r1[0] << " " << r1[1] << endl; // 0 1
    cout << r2[0] << " " << r2[1] << endl; // 1 2
    cout << r3[0] << " " << r3[1] << endl; // 0 1

    assert(r1 == vector<int>({0, 1}));
    assert(r2 == vector<int>({1, 2}));
    assert(r3 == vector<int>({0, 1}));

    cout << "所有测试通过" << endl;
    return 0;
}
```

## 复杂度分析

遍历数组一次，每个元素只做一次补数计算和哈希表查询/插入，平均时间复杂度是 O(n)。哈希表最多存下 n 个元素，所以空间复杂度是 O(n)。相比暴力枚举的 O(n^2)，这是典型的“用空间换时间”的优化。

## 易错点

1. 先插入再查找，导致同一个元素被重复使用。修复方法是先判断补数是否存在，再把当前数放入哈希表。
2. 只记录数值不记录下标，最后找到了数却返回不了正确答案。修复方法是在哈希表中保存“数值 -> 下标”。
3. 遇到重复元素时覆盖了之前的下标，可能丢失更早的合法解。修复方法是通常保留第一次出现的位置，或者按题意决定是否覆盖。
