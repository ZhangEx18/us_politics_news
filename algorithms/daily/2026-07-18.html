单调栈：一次解决下一个更大元素

进阶
栈单调栈数组
如何把“为每个元素向右找第一个更大数”的暴力双循环，优化成线性时间？

直觉理解

单调栈的本质，是把“还没找到答案的人”按某种顺序排好队。以“下一个更大元素”为例，我们从左到右扫描数组，栈里保存那些右侧还没遇到更大值的元素下标，并且让它们对应的值保持单调递减。这样一来，新来的元素一旦比栈顶大，就说明它正好是栈顶元素的下一个更大元素，于是可以立刻把栈顶出栈并记录答案。继续弹，直到栈顶不再比当前元素小。这样每个元素最多进栈一次、出栈一次，原本需要双重循环的比较被压缩成了“一次扫描，顺手结算”。你可以把它想成：栈里放的是一群等待“被拯救”的位置，当前元素就是一把钥匙，谁先被它打开，谁就先得到答案。

算法思路

先明确目标：对数组中的每个位置 i，找它右边第一个比 nums[i] 更大的元素；如果不存在，就记为 -1。最直接的做法是对每个 i 都向右枚举，直到遇到更大的数，时间复杂度是 O(n^2)，当数组很长时会明显超时。单调栈的思路是把这些重复比较“打包处理”。 从左到右遍历数组。维护一个栈，栈中存的是下标，而不是数值本身。栈对应的数值从栈底到栈顶严格递减，这意味着栈里的人都还在等待右侧更大的元素。当前遍历到 nums[i] 时，只要它比栈顶下标对应的值更大，就说明它是栈顶那个位置的下一个更大元素。于是不断弹出栈顶，并把答案设为 nums[i]。这个过程会一直持续，直到栈空或者栈顶元素已经不小于当前值。之后，把 i 入栈，表示它自己也开始等待未来的更大元素。 为什么这样是对的？因为栈顶总是离当前最近、且还没被解决的元素。如果当前元素连栈顶都能“打败”，那它也一定能打败更靠下的那些更小元素；这些元素的答案都可以直接确定。等遍历结束后，栈里剩下的元素右侧再也没有更大的数，答案保持为 -1 即可。 如果题目要求的是“循环数组”的下一个更大元素，只需把数组长度看成 2n，第二轮遍历时只负责补充右侧信息，但只有第一轮位置需要真正写答案。单调栈的核心思想不变：利用单调性减少无效比较，把“未来谁来解决我”这件事变成一次顺手的出栈操作。

Python 示例

from typing import List


def next_greater_elements(nums: List[int]) -> List[int]:
    """返回每个元素右侧第一个更大元素；如果不存在则为 -1。"""
    n = len(nums)
    ans = [-1] * n
    stack = []  # 存下标，栈内对应值保持单调递减

    for i, x in enumerate(nums):
        # 当前元素比栈顶元素大，说明它就是栈顶的下一个更大元素
        while stack and nums[stack[-1]] < x:
            j = stack.pop()
            ans[j] = x
        stack.append(i)

    return ans


def next_greater_elements_circular(nums: List[int]) -> List[int]:
    """循环数组版本：数组末尾后面接着数组开头。"""
    n = len(nums)
    ans = [-1] * n
    stack = []

    # 遍历两轮，第二轮只用来补充前面元素的答案
    for i in range(2 * n):
        x = nums[i % n]
        while stack and nums[stack[-1]] < x:
            j = stack.pop()
            ans[j] = x
        # 只有第一轮才入栈，避免重复下标无限压栈
        if i < n:
            stack.append(i)

    return ans


def _run_tests():
    # 基础测试
    assert next_greater_elements([2, 1, 2, 4, 3]) == [4, 2, 4, -1, -1]
    assert next_greater_elements([1, 2, 3, 4]) == [2, 3, 4, -1]
    assert next_greater_elements([4, 3, 2, 1]) == [-1, -1, -1, -1]
    assert next_greater_elements([1, 1, 1]) == [-1, -1, -1]

    # 循环数组测试
    assert next_greater_elements_circular([1, 2, 1]) == [2, -1, 2]
    assert next_greater_elements_circular([3, 8, 4, 1, 2]) == [8, -1, 8, 2, 3]
    assert next_greater_elements_circular([5, 4, 3, 2, 1]) == [-1, 5, 5, 5, 5]

    print("全部测试通过")


if __name__ == "__main__":
    _run_tests()

C++ 对照

#include <bits/stdc++.h>
using namespace std;

vector<int> nextGreaterElements(const vector<int>& nums) {
    int n = (int)nums.size();
    vector<int> ans(n, -1);
    stack<int> st; // 存下标，栈内对应值单调递减

    for (int i = 0; i < n; ++i) {
        while (!st.empty() && nums[st.top()] < nums[i]) {
            ans[st.top()] = nums[i];
            st.pop();
        }
        st.push(i);
    }
    return ans;
}

vector<int> nextGreaterElementsCircular(const vector<int>& nums) {
    int n = (int)nums.size();
    vector<int> ans(n, -1);
    stack<int> st;

    for (int i = 0; i < 2 * n; ++i) {
        int x = nums[i % n];
        while (!st.empty() && nums[st.top()] < x) {
            ans[st.top()] = x;
            st.pop();
        }
        if (i < n) st.push(i);
    }
    return ans;
}

int main() {
    vector<int> a = {2, 1, 2, 4, 3};
    vector<int> b = nextGreaterElements(a);
    for (int x : b) cout << x << ' ';
    cout << '\n';

    vector<int> c = {1, 2, 1};
    vector<int> d = nextGreaterElementsCircular(c);
    for (int x : d) cout << x << ' ';
    cout << '\n';

    return 0;
}

复杂度分析

每个元素最多入栈一次、出栈一次，所以总时间复杂度是 O(n)。栈中最多保存 n 个下标，因此空间复杂度是 O(n)。相比暴力做法的 O(n^2)，单调栈把重复比较大幅压缩掉了。

易错点

  1. 把栈里存成数值而不是下标，后续无法准确回填答案，尤其是重复元素时会出错；修复方法是统一存下标，再通过 nums[下标] 比较和赋值。
  2. 把单调方向写反了：下一个更大元素要维护“递减栈”，如果误写成递增栈，就会把不该弹出的元素弹掉；修复方法是牢记“新元素来解决比自己小的人”，因此栈顶必须是比当前小的才弹。
  3. 循环数组题目中把下标重复入栈，导致同一位置被多次处理甚至死循环；修复方法是只在第一轮入栈，第二轮仅用来触发更新答案。

延伸练习

  1. 把“下一个更大元素”改成“下一个更小元素”，要求输出每个位置右侧第一个更小数。
  2. 扩展到循环数组版本，并额外返回每个位置距离下一个更大元素的步数，而不只是元素值。
